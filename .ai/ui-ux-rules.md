# UI & UX Rules - KC-App

## Shared Principles

- UI must be clean, premium, calm, and visually structured.
- Avoid clutter, excessive cards, or generic template-looking UI.
- All user interactions must provide immediate visual touch feedback (ink response, active state).
- Empty states must explain the situation and suggest a clear next action (`AppEmptyView`).
- Error states must provide an explicit retry option (`AppErrorView`).
- Skeleton loaders or clean loading views (`AppLoadingView`) must preserve screen layout.
- Destructive actions require clear confirmation dialogs.
- Form fields require validation and clear inline error messaging.

## Customer App Specific UX

- Prioritize imagery, collection discovery, and visual storytelling.
- Use large design images and editorial spacing.
- Provide smooth, effortless browsing without aggressive popups.
- Avoid dashboard-style or number-heavy operational controls.
- **Strict Prohibition**: Do NOT use e-commerce UI patterns (price tags on main cards, add-to-cart buttons, cart icons, or buy-now actions).
